# Source-listed discovery attributes

`lib/approved-guide-attributes.json` is an initially empty, separately reviewed input. Entries become eligible for public display only when they have an exact directory `guide_id`, a supported `kind` (`species`, `method`, `trip_type`, `business_name`, or `person_name`), a nonempty `value`, a source URL, type, locator and valid nonfuture `reviewed_on` date, an `evidence_scope` (`operator_advertises` or `industry_lists`), `editorial_status: "approved"`, and `publication_approved: true`. An editorial approval requires a separate authorized decision; this branch grants none.

Missing, unknown, rejected, pending, conflicting or malformed records do not reach client props or the profile panel. Identical approved evidence is deduplicated, and distinct explicitly sourced relationships remain separate. `lib/guide-evidence-holds.json` independently blocks the known held guide IDs and the discontinued Grindstone Lakes offering. Those holds require independent evidence and authorized review before their data can change. Attributes describe source-listed business offerings or names; they do not certify personal expertise, a credential, booking, or a current trip.

An optional `relationship` may carry `species`, `method` and `waterway` only when the same cited source explicitly connects at least two of them. The source attached to the attribute applies to the relationship. Separate attributes never imply a combination, and broad labels are never expanded into narrower species. Exact filters may independently match multiple attributes, so the UI explains that this is not proof of one trip.

`docs/research/BATCH13_EXTENDED_PROPOSAL.json` is a deterministic pending proposal derived from the frozen MVP candidate, not an input to the public app. The initial proposal and source snapshot remain unchanged. Its 81 newly representable facts and seven previously proposed names still require independent source and identity review. Eleven location/accessibility facts remain outside this contract. The local/CI fixture runner builds an explicit Git tree in a disposable workspace with synthetic records and is visibly labeled. It never modifies the primary checkout’s source data or build output. Never deploy a fixture build.

## Guide search tags

The public directory uses approved fishing tags, search names and business keywords from `lib/directory-guide-tags.json`. Each entry matches the guide’s registration, registry name and business. Private notes and source decisions belong in private project storage. Publish only the approved labels. Tags support discovery and carry no new location, identity, licensing or combined-trip claim.
