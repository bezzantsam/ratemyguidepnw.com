## Confirmed findings

### Unresolved cross-state link is displayed as a single captain

- **Where:** `lib/washington-reconciled.ts:13,20`, `lib/directory.ts:41`, `lib/washington.ts:34`, `app/guides/[slug]/page.tsx:11`, `app/washington/page.tsx:2`.
- **Reproduction:** Run `node --test tests/independent-release-review/boundaries.test.mjs`. The last test finds the record for `OG.0003982`, confirms that its review note says the business match requires review, and expects `washingtonRecordForOregon` to withhold the link. It instead returns the record. The raw Washington source contains Daniel Benowitz / PHD Guide Service; the Oregon source contains Daniel Richman-Benowitz / PHD Fishing Guide Service. The importer drops the Washington name, the unified directory marks the Oregon entry as both states, and the Oregon profile says “This captain has a matching listing” and “We maintain a single captain profile.” The note appears too, but does not prevent the association.
- **Expected / actual:** An unresolved association should remain separate or explicitly provisional until reviewed. The current code applies the association as a match and suppresses the separate Washington listing. This is not evidence that the two people are different; it is evidence that an association explicitly needing review is already used as established.
- **Impact:** Visitors may attribute a Washington listing and state coverage to the wrong Oregon person, and cannot independently find the suppressed Washington record. This undermines the identity boundary even though the profile includes a caution.
- **Suggested fix:** Add an explicit reviewed identity-link decision and gate all suppression, state badges, shared profiles and cross-state claims on it; preserve unresolved source records independently with stable IDs. Audit the other links, including the one marked not identity-verified, using the same rule.

### A new Washington source row is discarded solely for sharing a name

- **Where:** `lib/washington.ts:9-13,34`; the behavior is also intentionally captured in `tests/washington-stable-ids.test.mjs` under “adding excluded cross-state sources”.
- **Reproduction:** The third test in `node --test tests/independent-release-review/boundaries.test.mjs` supplies `{name:'Tony Fisher', business:'Unrelated hypothetical outfit', source:'Unreviewed source', notes:null}` to `mapWashingtonGuides`. Expected: reject the unallocated source key or return a separately reviewed ID. Actual: `[]`, without requiring an allocation or checking the business/source. The test fails with “Missing expected exception.” The row is synthetic and does not claim a real namesake exists.
- **Impact:** A future import can silently lose a different person with a common matching name; the importer bypasses its normal unreviewed-ID error, making loss difficult to notice.
- **Suggested fix:** Exclude only individually reviewed source keys/IDs, not every row bearing a name; unknown keys should require a stable ID and identity review.
