# WSGA active-member ingestion: blocked draft

Status: **not ready for import**. This branch adds review tooling and synthetic tests, not a completed live ingestion. The existing directory is unchanged. The requested exact active-source, matched, net-new and manual-review counts are unknown: `WSGA_CAPTURE_STATUS.json` deliberately uses `null`, not zero. No live source CSV or JSON report has been produced.

## Baseline and identity

This branch is based on main `218c4c91a17ec09600833d041bac32cb90246e2a`. `lib/washington-raw.json` contains 163 source rows, including 91 labeled WSGA, WSGA/CAPS or WSGA/local; these are existing source rows, **not** a count of current active WSGA members, unique guides or new candidates. It contains name, business, source and notes, but no per-row URL/contact or capture timestamp. `lib/oregon-guides.json` contains 1,027 records with registration, name, business and website. `lib/washington-reconciled.ts` contains curated, sometimes explicitly provisional, cross-state associations. `lib/washington.ts` on this baseline generates positional IDs and suppresses some source names; a `washington-raw-index` in the output identifies a source row for review, not a durable public or database ID. The Supabase scaffold has a `guides` table with name, outfit, jurisdiction, license and URL, but no separate business-person or source assertion table. The hosted state was not inspected or changed.

The review script reads all three local source files; it does not mutate them. An `exact_source_duplicate` means a single WSGA-attributed Washington row agrees on normalized name plus business (or domain where available), with no detected anomaly. It does **not** establish legal identity, present membership, a verified credential or permission to overwrite a record. Name-only, cross-state, conflicting or multiple candidate matches go to review. Same-domain different-business and reused-email signals are flagged. Shared business/domain alone never merges people; a name variant attached to an existing curated cross-state association is a review candidate. Preserve source names and potential aliases for an editor to assess. Exact string and conservative similarity checks cannot rule out all duplicates; `net_new_candidate` means no match found by this limited comparison.

## Source access and current limitation

The page's web-reader view displays an **In Memory** section separately from **Active Professional Guides and Charter Operators**; the source's membership/license language is not independent licensing verification. The reader exposed some suspicious links, including a website-labeled email and an Instagram label pointing to a different domain, which need preservation and human review. These observations are not a complete capture and should not be imported.

On 2026-11-17 direct shell `curl` of `https://waguidesassociation.org/robots.txt` failed with DNS error 6. The web reader returned an inaccessible-URL error for that robots file, with no HTTP status or rules; its cached/rendered member page is not a byte-for-byte capture. No explicit terms were found on the directory page. Because robots and applicable terms could not be assessed, this branch does not convert that rendering into a dataset, claim a count, follow member links or perform a live scrape. Retry only after network availability changes; stop on disallow, inaccessible robots, access controls, or adverse terms. Do not bypass them.

## Safe review procedure

1. Inspect current source terms and network permission; use the user-approved public source only. On an environment where its robots file is readable, run the command below once. It fetches robots then the directory at least two seconds later, honors longer bounded crawl-delay, follows only same-host HTTPS redirects and stops on robots failure or disallow. It stores the unmodified source bytes, robots and SHA-256/timestamp manifest in a **new private directory**. HTTPS verification remains enabled. `--terms-reviewed` records the operator's affirmative check; it is not a substitute for that check.

   ```sh
   python3 scripts/wsga_capture.py --terms-reviewed --out /private/path/wsga-capture
   python3 scripts/wsga_review.py --capture-dir /private/path/wsga-capture --out /private/path/wsga-review
   ```

2. Verify the parser against the actual HTML before trusting any output. It has only synthetic fixture coverage: it stops at the next peer/higher heading and fails on unexpected member structures, but has not seen source HTML. Manually reconcile every active entry and source pagination against rendered content; verify raw URLs, malformed/mismatched links, and every email/phone. Confirm memorial names are absent. Compare the JSON totals and CSV rows to the source, identify misses and rerun after fixing parser/tests. Do not silently fix bad source links. JSON retains source spellings; CSV escapes spreadsheet formula prefixes.
3. Review all exact source-row duplicates, likely duplicates and anomalies, including shared businesses and cross-state aliases. Check all likely net-new people against current live directory records using independently supported evidence; this repo baseline is not proof of the current production state. Keep multiple people at one outfitter distinct. Review existing provisional mappings separately. No source listing independently verifies current WA/OR credentials.
4. Stage a separate, source-attributed candidate proposal retaining original URL, timestamp, source text, link anomalies, alias and person-to-business relationships. Agree on a schema preserving those relationships and record-level provenance, including `listed` or `draft` rather than verified credentials. Review a reversible diff and backup/rollback plan. **Obtain approval before any production write or deployment.** This branch contains no import or database mutation.

A synthetic end-to-end run makes both CSV and JSON; it is not live-source evidence. Ten existing NOAA tests also passed. The broader Python discovery attempted 21 tests but had one import error because `beautifulsoup4` is not installed in this environment; no network install was attempted. Existing production, dataset, environment and checkout files were preserved.
